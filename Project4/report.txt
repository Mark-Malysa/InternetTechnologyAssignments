Part B: Wireshark/TShark Instructions (guided by your sample run)
-----------------------------------------------------------------
Use the actual destination IP you saw in your trace. From the latest ilab run:
- Destination hostname: www.princeton.edu
- Destination IP observed: 104.18.4.101 (Cloudflare front-end for Princeton)

Capture steps (Wireshark GUI):
1) Start Wireshark on the ilab machine. Pick the interface that has internet access (often `eth0` on ilab; if unsure, look for the one with increasing packet counters).
2) Set a display filter to see only relevant traffic:  
   `icmp or ip.addr == 104.18.4.101`  
   (If your trace shows a different destination IP, replace 104.18.4.101 with that IP. Using the literal IP avoids name-resolution mismatches.)
3) Click Start (blue fin icon) to begin capturing **before** running traceroute.
4) In a terminal, run:  
   `python3 traceroute_skeleton.py`
   - This uses `IP_RECVERR`, which works only on Linux (ilab/WSL/Ubuntu). It will not work on macOS natively.
5) Wait for traceroute to finish (you saw destination at hop 12 in your sample).
6) Stop the capture (red square).
7) Save the capture as `traceroute.pcapng`.

Optional TShark (CLI) capture instead of GUI:
```
sudo tshark -i eth0 -f "icmp or host 104.18.5.101" -w traceroute.pcapng
```
Replace `eth0` if your interface differs; replace the host IP if your destination IP differs.

How to find packets for the questions:
- First request packet: first UDP probe to the destination. In the new pcap: src IP = your ilab host (128.6.13.25), dst IP = 104.18.4.101, protocol = UDP, TTL = 1, sport ≈ 33616, dport ≈ 33435.
- First router response: ICMP Time Exceeded (Type 11, Code 0) from hop 1 (128.6.13.1) back to you; outer IP protocol = 1; inner IP shows your original UDP probe to 104.18.4.101.
- Destination response: ICMP Destination Unreachable, Port Unreachable (Type 3, Code 3) from 104.18.4.101 back to you (seen in the new pcap).
- Counting routers: from the ICMP Time Exceeded sources before the first Port Unreachable, there are 14 routers; destination reply occurs next (effective hop ~15). If your traceroute text output shows fewer/more lines, use the text output, but the pcap shows 14 distinct routers then the destination.
- TTL at destination: corresponds to the hop where the destination replied; based on the pcap, this is hop ~15.
